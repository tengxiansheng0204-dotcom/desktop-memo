# 桌面备忘 · macOS Beta

把待办事项放在桌面上。设置首次提醒时间后，应用会通过 Mac 系统通知提醒；没有勾选完成，就按设定间隔继续提醒，默认每 15 分钟一次。

这是供试用和反馈的 Beta 版本。[云端构建](https://github.com/tengxiansheng0204-dotcom/desktop-memo/actions/workflows/build-beta.yml)分别在 Apple 芯片和 Intel macOS 虚拟机上执行测试、编译、启动检查与打包；两种架构都成功后，才生成可下载的预发布版本。窗口交互、系统通知和登录启动仍需实际使用验证。

## 下载与安装

下载入口：[GitHub Releases](https://github.com/tengxiansheng0204-dotcom/desktop-memo/releases)。若尚未显示版本，请先查看上方的构建状态。

需要 **macOS 13 或更新版本**。打开苹果菜单 →“关于本机”，按芯片选择包：

| 你的 Mac | ZIP 文件 | DMG 文件 |
| --- | --- | --- |
| Apple 芯片，例如 M1、M2、M3、M4 | `DesktopMemo-macOS-arm64.zip` | `DesktopMemo-macOS-arm64.dmg` |
| Intel 处理器 | `DesktopMemo-macOS-x86_64.zip` | `DesktopMemo-macOS-x86_64.dmg` |

计划分别提供两种架构的包，而非通用二进制。任选对应架构的 ZIP 或 DMG：解压 ZIP 或打开 DMG 后，把 `DesktopMemo.app` 拖入“应用程序”，再双击打开。已有旧版本时，先从菜单栏退出应用，再替换。

Beta 包采用 **ad hoc 本地签名**，没有 Developer ID 签名，也**没有经过 Apple 公证**。构建和试用不要求付费 Apple Developer 账号，但 Gatekeeper 可能阻止打开；本地签名不表示 Apple 已验证发布者或检查过应用安全性。

仅在你确认下载来自可信发布者、文件未被篡改，并接受试用风险时，才考虑为这个应用单独放行：先尝试打开，再到“系统设置 → 隐私与安全性”，找到对应应用的“仍要打开”，确认应用名称后按系统提示操作。这是 Apple 提供的单个应用例外方式，是否可用取决于系统和设备管理策略。若提示含有恶意软件、会损坏电脑或文件已损坏，请停止安装并联系发布者。[Apple 官方说明](https://support.apple.com/zh-cn/102445)

首次打开后，在便签顶部点击“开启”并允许通知。需要登录后自动运行时，在右上角“…”菜单开启“开机启动”；若系统要求批准，到“系统设置 → 通用 → 登录项”查看。

## 使用

点击“添加备忘录”，填写标题和补充说明，设置未来的首次提醒时间，选择重复间隔后保存。可选间隔为 5、15、30、60 或 120 分钟，最多保留 20 条未完成事项。

例如，14:00 提醒“提交周报”，间隔为 15 分钟：未完成时会在 14:00、14:15、14:30……提醒。点击事项前的圆圈，或使用通知中的“已完成”，会停止后续提醒。“15 分钟后提醒”会把下一次提醒推迟到当前时间的 15 分钟后，之后按原间隔继续。通知操作的展开方式取决于 macOS 版本。

便签可以拖动、调整大小和置顶。关闭便签窗口后，应用继续在菜单栏运行；点击菜单栏图标可重新打开。已完成事项可以恢复，恢复后的首次提醒设为 15 分钟后。删除需要确认，删除后无法撤销。

## 提醒的限制

- **保持应用后台运行，才能持续补充重复提醒。** 关闭窗口不会退出；菜单栏“退出”会结束后台进程。
- 应用预排一个有限的本地通知队列，最多 60 条，并约每 20 秒补充。退出后，已经排队的通知仍可能出现；队列耗尽后不再提醒。
- 启动或睡眠唤醒时，对逾期事项补一次提醒，再继续安排后续周期；不会逐条重放所有错过的提醒。关机、睡眠时不保证准点显示。
- 专注模式、通知权限、声音和通知样式会影响显示。遇到没有提醒，先检查应用是否仍在运行，以及“系统设置 → 通知”中的权限。
- 勾选完成会撤销待发通知并移除已送达通知；系统已经开始展示的通知可能短暂出现。
- 全屏应用、多个桌面、台前调度、登录启动和休眠唤醒的表现尚待实机验证。
- 仅在这台 Mac 上提醒，不同步到手机或微信。Beta 阶段请先用不重要的事项验证提醒行为。

## 本机数据与备份

无需账号，应用不使用服务器，也不主动发起网络请求。备忘录保存在：

```text
~/Library/Application Support/DesktopMemo/memos.json
```

备份时先退出应用，再复制此文件。重新打开应用会恢复已保存的内容。若数据损坏或不合法，应用会保留原文件、提示错误并暂停编辑及提醒；请先备份原文件，再恢复有效备份。不要在应用运行时直接编辑数据文件。

## 从源码构建

需要 macOS 13+ 和包含 Swift 5.9+ 的 Apple 开发工具。无需 Apple Developer 付费账号。

1. 下载完整源码并解压。如果没有开发工具，在终端执行 `xcode-select --install`，完成安装。
2. 在终端输入 `cd `，把源码文件夹拖进去，然后回车。
3. 运行：

   ```bash
   bash build-mac.command
   ```

4. 脚本会先运行单元测试，再编译、组装并进行 ad hoc 签名，在 `dist/` 中生成 `DesktopMemo-macOS-<架构>.zip`、`DesktopMemo-macOS-<架构>.dmg` 和 `DesktopMemo-macOS-<架构>-SHA256SUMS.txt`，其中架构为 `arm64` 或 `x86_64`；不保留单独的 `.app`。打开 DMG 或解压 ZIP 即可取出应用。使用 `bash build-mac.command --no-open` 可在构建后不打开访达。任一步骤失败应先查看错误，不要将失败构建用于试用。
5. 把应用拖入“应用程序”并打开，开启系统通知。

本地构建默认使用当前 Mac 的架构。可用 Xcode 打开 `Package.swift` 阅读和调试代码；验证系统通知时，请运行完整的 `.app` 包。也可单独执行 `swift test` 运行时间规划测试。

## 验证与反馈

自动验证包含时间规划测试、本地保存及异常文件测试、两个架构的原生编译、应用启动检查、签名完整性、DMG 与 SHA-256 校验。请以对应版本的 Actions 日志和发布说明确认哪些检查已通过。**UI 和系统集成仍未验收**；启动检查不能替代通知显示、通知按钮、窗口、登录启动和睡眠唤醒测试。

首次试用建议设置 1 分钟后到期、每 5 分钟重复的事项，确认首次通知和两次重复通知；随后勾选完成，确认通知停止。再分别检查通知中的“已完成”“15 分钟后提醒”、关闭窗口后的后台提醒、重启后的数据恢复，以及睡眠唤醒。

反馈时请提供 macOS 版本、芯片类型、应用版本、复现步骤和实际表现；截图中请遮去私人的备忘录内容。版本说明见 [RELEASE_NOTES.md](RELEASE_NOTES.md)。
